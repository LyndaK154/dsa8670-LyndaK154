One thing I learned from this week's readings what how GitHub keeps track of the changes made to a project. I found it useful that you can go back to a previous version of a project if something goes wrong. Instead of having to completely restart a project, you can return to an earlier version and continue from there. I also learned that on Mac, I can open certain files using TextEdit, make changes, and then have those changes reflected in the project in GitHub. This helped me better understand how GitHub keeps track of changes made to files.

One challenge I faced while working in GitHub was understanding the instructions and knowing exactly where to go. Sometimes I understood what the instructions were asking me to do, but I was unsure what I needed to open or where I needed to click to complete the step. I used online forums and the GitHub Community to find explanations from other users. Sometimes I would use the image tab in google as well to see where certain buttons were on the page.

GitHub is extremely helpful for team projects because it allows multiple people to work on the same project while being able to keep track of changes everyone makes. If someone makes a mistake or something does not work as expected, the team can look at previous versions instead of starting over. GitHub is also extremely user friendly for group projects. As someone who is new to GitHub and learning myself, despite the challenges I have faced, it is easy to understand once you know where to go and what to do. This seems to make it easier for team members to collaborate and keep their work organized. This also makes it easy to track a project over time.
